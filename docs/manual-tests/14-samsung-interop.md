# 14. 삼성 갤러리 연동

검토: `../SAMSUNG_GALLERY_INTEROP.md`

| ID | 시나리오 | 기대 결과 | 상태 | 메모 |
|---|---|---|---|---|
| SS-01 | 삼성 갤러리에서 사진 ♥ → MediaStore 조회 | `is_favorite=1` 로 나온다 | ⬜ | **이 한 건에 즐겨찾기 연동 여부가 걸려 있다** |
| SS-02 | 삼성에서 ♥ → 우리 앱 "즐겨찾기만 보기" | 그 사진이 보인다 | ⬜ | SS-01 이 통과해야 의미가 있다 |
| SS-03 | 우리 앱에서 ♥ → 삼성 갤러리 즐겨찾기 | 그 사진이 보인다 | ⬜ | 반대 방향 |
| SS-04 | 우리 앱에서 "앨범으로 이동" → 삼성 갤러리 | 옮긴 폴더에 보인다 | ⬜ | 파일을 실제로 옮기므로 될 것으로 본다 |
| SS-05 | 삼성 갤러리에서 앨범 생성·이동 → 우리 앱 | 새 폴더가 앨범 목록에 뜬다 | ⬜ | |
| SS-06 | 삼성 갤러리 provider 노출 확인 | `dumpsys package com.sec.android.gallery3d` | ⬜ | 있어도 문서화 안 된 것이라 기대지 않는다 |
| SS-08 | Drive 연결 (GCP 등록 후) | 계정 선택 → 동의 → "연결되었습니다" | ⬜ | 2026-09-23 GCP 등록 완료. 실패 시 로그로 UNREGISTERED_ON_API_CONSOLE / access_denied 구분 |
| SS-09 | `drive.file` 로 바꾼 빌드 + 피커로 폴더 지정 | 고른 폴더 **안의 기존 파일**이 `files.list` 에 보이는지 | ⬜ | **이 결과에 따라 피커 기능의 성격이 갈린다**(탐색 가능 vs 업로드 대상 지정만) |
| SS-07 | 삼성에서 숨긴 앨범 | 우리 앱에서 어떻게 보이는지 기록 | ⬜ | 삼성 숨김과 우리 숨김은 별개다 |
