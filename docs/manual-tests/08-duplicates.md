# 08 · 중복 사진 (완전 중복만)

준비: 같은 사진 파일을 두 번 저장한다 (예: 카톡에서 같은 사진 2회 저장, 또는 파일 앱으로 복사). 갤러리 ⋮ → 중복 사진.

| ID | 시나리오 | 기대 결과 | 상태 | 메모 |
|---|---|---|---|---|
| DUP-01 | 첫 진입 → "검사" | 진행률(파일 내용 비교 n/m) 표시. 대상이 많으면 알림에도 진행률. 화면을 나가도 계속 | ⬜ | 해시 대상은 크기가 겹치는 파일만 |
| DUP-02 | 검사 완료 | 같은 파일 그룹이 낭비 용량 큰 순으로, 상단 "n그룹 · 중복 m개 · x MB 절약 가능" | ⬜ | |
| DUP-03 | 그룹 안 기본 선택 | "유지" 라벨 1개(백업된 것 우선, 없으면 먼저 저장된 것), 나머지는 빨간 체크(제거 대상) | ⬜ | |
| DUP-04 | 썸네일 탭 | 제거 대상 ↔ 유지 토글. "기본 선택"으로 되돌리기 | ⬜ | |
| DUP-05 | "n개 휴지통으로" | 시스템 동의 → 휴지통 이동 → 그룹에서 사라지고 요약 갱신 | ⬜ | 완전 삭제는 없음 |
| DUP-06 | 연속 촬영한 비슷한 사진 3장 | 그룹으로 잡히지 **않음** (바이트가 다르므로) | ⬜ | 설계 의도 — 유사 사진은 다루지 않는다 |
| DUP-07 | 같은 사진의 리사이즈/재압축본 | 잡히지 않음 (정상) | ⬜ | |
| DUP-08 | 다시 검사 | 이미 해시한 파일은 건너뛰어 훨씬 빠름. 사진을 편집(수정 시각 변경)하면 그것만 다시 해시 | ⬜ | |
| DUP-09 | 검사 중 "취소" | 워커 중단, 지금까지 해시는 유지 | ⬜ | |
| DUP-10 | 6천 장 전체에서 검사 시간·발열 | 크기 충돌 파일 수에 비례. 대용량 영상이 크기 충돌이면 오래 걸릴 수 있음 | ⬜ | 배터리 부족 시 대기 |
