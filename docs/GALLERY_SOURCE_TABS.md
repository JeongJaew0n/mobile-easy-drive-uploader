# 갤러리 출처 탭

갤러리 상단의 **전체 / 카메라 / 스크린샷 / 다른 앱** 탭. 진행 계획은 `docs/plans/gallery-source-tabs/`.

## 1. 왜

한 목록에 카메라 사진과 카카오톡 이미지가 날짜순으로 섞여 들어온다.
이 기기 기준 카메라 4023장 사이에 카카오톡 1013장이 끼어 있어 찍은 사진을 훑어보기 어려웠다.

## 2. 분류 규칙 — `MediaSource`

`MediaItem.relativePath` **하나만** 본다. 이미 조회에 들어 있는 값이라 MediaStore 재조회가 없다.

| 출처 | 규칙 | 이 기기 |
|---|---|---|
| 스크린샷 | 경로에 `Screenshots` 세그먼트 | 469 |
| 카메라 | 최상위가 `DCIM` (스크린샷 제외) | 4498 |
| 다른 앱 | 나머지 | 1212 |

판정 순서가 중요하다 — **스크린샷을 먼저 본다.** `DCIM/Screenshots` 가 있어서 DCIM 부터 보면 카메라로 잡힌다.

### 왜 폴더 이름이 아니라 최상위 경로인가

실기기 분포를 보고 정했다.

```
DCIM/Camera/                4023    카메라 앱
DCIM/중국 연태 …/  DCIM/으으/   444    사용자가 직접 만든 앨범
DCIM/CandyCam/ DCIM/행복이/     20    카메라류 앱
DCIM/Screenshots/            461    스크린샷
Pictures/KakaoTalk/         1013    다른 앱
Pictures/페이북·Naver·Somoim…   40    〃
Download/  Documents/…        95    〃
SilentCamera/ (최상위)         17    〃
```

폴더 이름으로 카메라 앱을 가려내려 하면 기기·앱마다 달라 끝이 없다.
`DCIM` 아래 직접 만든 앨범(중국 연태·으으)도 "내가 남긴 사진"이라 카메라 탭에 둔다.

`SilentCamera/` 처럼 최상위에 쓰는 카메라류 앱은 '다른 앱'으로 간다.
아쉽지만 "DCIM 밖에 쓰는 앱"이라는 사실 자체는 맞고, 규칙이 한 줄로 유지된다.

## 3. 탭과 기존 필터

**탭을 바꾸면 즐겨찾기·기간·카테고리·백업 안 됨이 모두 풀리고 선택도 해제된다**(2026-09-17 사용자 결정).
탭은 "지금 무엇을 보고 있는가"의 최상위 기준이라, 이전 탭의 조건이 따라오면
결과가 비어 보이는 이유를 알기 어렵다.

## 4. 거르는 순서

```
observeMedia(filter)
  → 탭(출처)        ← 가장 바깥
  → 백업 안 됨
  → 카테고리
  → dayCounts 계산   ← 기간 선택 달력이 이 탭의 날짜만 보여주도록
  → 기간
```

**앨범(이동 대상) 목록만은 탭 적용 전 목록에서 뽑는다.** 그러지 않으면
스크린샷 탭에서 다른 폴더로 옮길 수 없다.

## 5. 화면

`GalleryTopBar` 와 한 `Column` 에 묶인 `PrimaryTabRow`.
선택 모드에서는 상단바가 통째로 `SelectionTopBar` 로 바뀌므로 탭도 함께 사라진다 —
탭을 누르면 선택이 풀리는데 선택 상단바 옆에 두면 실수로 누르기 쉽다.

항목이 0인 탭도 계속 보인다. 데이터에 따라 탭이 생겼다 사라지면 위치가 흔들린다.
개수는 라벨에 넣지 않는다 — 세려면 전체 목록을 네 번 훑어야 하고, 지금 탭의 개수는 상단바에 이미 있다.

## 6. 검증

- 단위 테스트: `MediaSourceTest`(경로 분류 경계), `GalleryViewModelTest`(탭 가르기·필터 해제·같은 탭 재선택)
- 실기기(2026-09-17, Galaxy S23+): 탭별 개수 4498 + 469 + 1212 = 6179 = 전체.
  스크린샷 탭의 기간 달력 연도가 2023~2026 으로 실제 분포와 일치.
  탭 전환 시 "백업 안 됨" 해제 확인. 선택 모드에서 탭 사라짐 확인.
  스크린샷 탭에서도 앨범 이동 대상에 `DCIM/Camera` 4023개가 그대로 나옴.
