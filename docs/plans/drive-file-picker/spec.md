# drive.file 전환과 폴더 피커

## 왜

Drive 전체 접근(`https://www.googleapis.com/auth/drive`)은 restricted scope 다.
스토어에 공개하려면 Google 보안 심사(CASA)를 받아야 하고, 사용자에게는 "내 Drive 전부를
이 앱이 본다"는 동의를 요구한다. 갤러리를 백업하는 앱에 그건 과하다.

`drive.file` 은 **앱이 만든 파일과 사용자가 피커로 고른 항목**만 접근한다.
restricted 가 아니라 심사를 받지 않는다.

## 측정으로 확정된 전제 (SS-09, 2026-09-24)

`drive.file` 에서 **폴더 접근권은 그 안의 항목으로 상속되지 않는다.**

- 내 드라이브 루트: 빈 화면
- 앱이 만든 폴더 / 앱이 올린 파일: 보임
- 같은 폴더 안에 Drive 앱으로 만든 폴더: **안 보임** (앱 재시작 후에도)

그래서 피커는 **탐색기가 아니라 업로드 대상을 지정하는 장치**다.
폴더를 고르면 거기에 올릴 수 있을 뿐, 그 폴더에 원래 있던 파일은 끝까지 보이지 않는다.

이 제약은 화면 문구로 드러나야 한다. 사용자가 Drive 앱에서 보던 파일이
우리 앱에서 사라진 것처럼 보이면 고장으로 읽힌다.

## 무엇을 만드나

### 1. Drive 화면의 루트가 바뀐다

지금은 `내 드라이브` 의 실제 자식 목록이다. 앞으로는 **앱이 접근권을 가진 폴더들**이다.

```
Google Drive
├── (지정한 폴더 A)        ← 피커로 고름
├── (지정한 폴더 B)
└── Easy Gallery           ← 앱이 만드는 기본 폴더
[+ Drive 에서 폴더 고르기]
```

### 2. 피커 — 폴더는 못 고른다 (2026-09-24 측정)

`play-services-auth:22.0.0` 에 이미 다 들어 있다. 새 라이브러리도 WebView 도 필요 없다.
결과는 `tokenResponseParams` 의 `picked_file_ids` 로 온다.

그런데 **`PICKER_ALLOW_FOLDER_SELECTION="true"` 를 줘도 폴더는 선택되지 않는다.**
탭하면 안으로 들어갈 뿐이다. 그래서 **폴더 안의 파일을 하나 고르게 하고 그 `parents` 를 쓴다.**
읽지 못하는 폴더에도 쓸 수는 있다는 것을 확인했다(DRV-P5).

자세한 것은 `../../DRIVE_FILE_SCOPE.md`.

### 3. `setOptOutIncludingGrantedScopes(true)`

SS-10 에서 나온 문제를 막는다. 이걸 안 주면 계정에 남은 이전 `drive` 동의가
누적돼 토큰이 `[drive.file, drive]` 로 온다. 앱이 요청을 좁혀도 실제 권한은
좁아지지 않는다.

### 4. SS-11 — 권한이 끊겼을 때 복구

같은 인증 코드를 건드리므로 함께 고친다. 지금은 `AuthorizationRequiredException`
을 문구로만 바꿔서, 한번 끊기면 설정에서 연결 해제 후 재연결하는 것 말고는
빠져나갈 길이 없다. 예외에 `PendingIntent` 를 실어 보내고 화면이 그것을 띄운다.

## 범위 밖

- 고른 폴더 **안을 탐색**하는 기능. 위 전제대로 불가능하다.
- 기존 사용자의 권한 축소. 계정에서 앱 액세스를 지워야만 좁아진다(SS-10).
  앱이 대신 해줄 수 없다. 안내 문구로만 다룬다.
