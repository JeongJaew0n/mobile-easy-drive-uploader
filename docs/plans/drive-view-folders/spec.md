# 보기 전용 폴더 — Drive 의 다른 폴더도 앱에서 본다

2026-09-26 시작.

## 1. 요구

> 지금은 `Easy Gallery` 하나만 볼 수 있다. "볼 수 있는 폴더 추가" 버튼으로
> Drive 의 다른 폴더를 고르면 그 안도 볼 수 있게 하자. 업로드는 안 돼도 된다.

## 2. 지금 왜 안 되는가 — 권한의 문제다

`drive.file` 로는 **불가능하다.** 코드가 모자라서가 아니라 권한이 그만큼이다.
2026-09-24 기기에서 잰 결과(`docs/DRIVE_FILE_SCOPE.md` §1, DRV-P4·P5):

- 폴더에 접근권이 있어도 **그 안의 외부 파일은 보이지 않는다.** 권한은 자식으로 상속되지 않는다.
- 피커로 고를 수 있는 것은 파일뿐이고, 고른 그 파일만 보인다.
- 폴더 자체는 `files.get` 이 404 라 **이름조차 읽을 수 없다.**

그래서 지금의 "지정 폴더" 는 *올릴 수 있는 곳* 이지 *볼 수 있는 곳* 이 아니다.
`docs/DRIVE_FILE_SCOPE.md` §9 가 이 기능을 "범위 밖" 으로 적어둔 이유다.

## 3. 선택지

| | 방법 | 요구를 만족하나 | 비용 |
|---|---|---|---|
| A | `drive.readonly` scope 를 **추가로** 받는다 | **그렇다.** 내 드라이브 전체를 읽을 수 있다 | restricted scope. Play 프로덕션 공개 시 CASA 심사 |
| B | `drive.file` 유지, 파일을 여러 개 고르게 한다 | 아니다. "폴더" 가 아니라 고른 파일 몇 개만 보인다 | 없음 |
| C | 전체 `drive` scope | 그렇다 | A 와 같은 심사 + 쓰기 권한까지 요구해 과하다 |

**A 로 간다.** B 는 요구를 만족하지 못하고, C 는 읽기만 필요한데 쓰기까지 달라는 것이다.

### A 의 비용을 줄이는 방법 — 증분 동의

`drive.readonly` 를 **처음부터 요구하지 않는다.** 기본 설치는 지금처럼 `drive.file` 뿐이고,
사용자가 "볼 수 있는 폴더 추가" 를 누른 그 순간에만 한 번 더 동의를 받는다.

- 이 기능을 안 쓰는 사용자의 동의 화면은 **그대로**다.
- 나중에 프로덕션 공개가 문제가 되면 **이 버튼 하나만 내리면 된다.** 구조를 되돌릴 필요가 없다.

## 4. 설계

### 4.1 권한

```kotlin
const val DRIVE_SCOPE = ".../auth/drive.file"        // 기본. 업로드·앱이 만든 파일
const val DRIVE_READONLY_SCOPE = ".../auth/drive.readonly"  // 옵트인. 보기 전용 폴더용
```

- `UserPreferences.driveViewScopeGranted: Boolean` — 옵트인 여부.
- 토큰을 받을 때 요청 scope 는 `[drive.file]` 또는 `[drive.file, drive.readonly]`.
  `setOptOutIncludingGrantedScopes(true)` 는 그대로 둔다(SS-10). **끄면 안 된다** —
  끄면 계정에 남은 예전 전체 `drive` 동의가 다시 딸려 온다.
- 동의 결과의 `grantedScopes` 에 readonly 가 실제로 들어왔는지 **확인하고** 플래그를 켠다.
  사용자가 동의 화면에서 체크를 풀 수 있다.
- 플래그를 켠 뒤에는 캐시된 토큰을 버린다 — 옛 토큰에는 readonly 가 없다.

### 4.2 저장

```kotlin
@Serializable
data class ViewFolder(val id: String, val name: String)   // 이름을 읽을 수 있으니 별칭이 필요 없다
```

`PickedFolder`(업로드 대상)와 **별개 목록**이다. 둘은 성격이 다르다 —
지정 폴더는 올릴 수 있고 이름을 모르고, 보기 폴더는 못 올리고 이름을 안다.

### 4.3 화면

Drive 루트가 이렇게 된다.

```
내 드라이브
├── 여행 사진            ← 지정 폴더 (업로드 가능)
├── Easy Gallery         ← 기본 폴더
├── 2019 앨범  [보기 전용] ← 새로 추가되는 것
└── 카메라 업로드 [보기 전용]
[+ 볼 수 있는 폴더 추가]
```

- 보기 전용 폴더 안에서는 **업로드·새 폴더·이름 변경·이동·삭제가 없다.**
  `Capability` 집합에서 변경 계열을 빼는 것으로 처리한다 — 화면이 이미 그걸로 판단한다.
- **다운로드는 남긴다.** 읽기 권한으로 할 수 있고, 남의 폴더 사진을 기기로 가져오는 건
  이 기능을 쓰는 자연스러운 이유다.
- 목록에서 빼는 것은 루트 행의 ⋮ → "목록에서 제거". Drive 의 파일은 건드리지 않는다.

### 4.4 폴더 고르기

readonly 가 있으면 폴더를 **읽을 수 있으므로**, 피커를 우회할 필요가 없다.
이미 있는 `DriveFolderPickerSheet`(이동 대상 고르기)를 그대로 쓴다 —
내 드라이브부터 폴더만 나열하고 breadcrumb 으로 오르내린다.

즉 이 기능에서는 §2 의 에두른 흐름("폴더 안의 파일을 하나 고르세요")이 필요 없다.
그 흐름은 업로드 대상 지정에만 남는다.

## 5. 사람이 해야 하는 일

**GCP OAuth 동의 화면에 `drive.readonly` 를 추가해야 한다.**
등록되지 않은 scope 를 요청하면 authorize 가 실패한다. 코드만으로는 안 되는 단계다.

## 6. 범위 밖

- 보기 전용 폴더로의 업로드. 읽기 권한이라 불가능하고, 요구에도 "업로드는 안 돼도 됨" 이라 적혀 있다.
- 보기 전용 폴더의 이름 변경·삭제. 같은 이유.
- 내 드라이브 전체를 그냥 탐색하기. 권한상 가능해지지만 화면이 시끄러워진다.
  "고른 폴더만 보인다" 는 지금의 성격을 유지한다.
