# 하단 내비게이션 + 백업 배지 — 계획

2026-10-05. 사용자 결정: "하단으로 가자. 배지는 기본적으로 켜 놔." 근거와 견본은 `docs/UX_RESEARCH.md` §4(5번·3번),
견본 페이지 https://claude.ai/artifact/Ki2xyNBWPgdCpHiH7AytT8. 기기 테스트는 지시가 있을 때.

## 칸 넷

| 칸 | 화면 | 담는 것 |
|---|---|---|
| 사진 | `GalleryKey`(지금 갤러리) | 출처 탭 다섯(고른 사진부터). ⋮ 는 보기 거르기 셋(즐겨찾기만·백업 안 된 것만·카테고리) |
| 앨범 | `AlbumsKey` 새 화면(`feature/albums`) | 즐겨찾기·휴지통 바로가기 + 앨범 격자. 앨범을 누르면 `AlbumKey` — 그 앨범만 보는 갤러리 |
| 백업 | `BackupKey` 새 화면(`feature/backup`) | 업로드 요약·실패, 업로드 목록, 자동 백업, Drive 보기, 올린 사진 기기에서 삭제 |
| 메뉴 | `MenuKey` 새 화면(`feature/menu`) | 숨긴 사진, 중복 사진, 카테고리 관리, 자동 태그, 설정 |

## 규칙

- **아래 칸은 칸의 첫 화면에서만** 보인다. 하위 화면(설정·앨범 하나·상세보기)에서는 없다. 사진 칸에서 고르기 시작하면
  같은 자리를 선택 하단바가 쓴다.
- 칸을 바꾸면 백스택을 `[사진]` 또는 `[사진, 그 칸]` 으로 다시 놓는다 — 다른 칸에서 뒤로 가면 사진으로, 사진에서 뒤로 가면 앱을
  나간다(Material 의 시작 목적지 규칙). 칸마다 하위 기록을 따로 들고 있지는 않는다(1차).
- 사진 칸의 ViewModel 은 스택 맨 아래에 계속 있으므로 탭·스크롤이 칸을 오가도 남는다.
- 앨범 하나(`AlbumKey`)는 **갤러리 화면을 그대로 쓴다** — 출처 탭 대신 ← 와 앨범 이름. 선택·업로드·삭제가 그대로 된다.
  ⋮ → 앨범 시트(2026-09-28)와 앨범 막대는 없앤다 — 앨범 칸이 대신한다.
- "올린 사진 기기에서 삭제" 는 **지금 보는 목록**이 아니라 **올린 사진 전부(숨긴 것 제외)** 를 대상으로 바뀐다. 그래서 앱 안에서
  "N장을 휴지통으로 옮길까요?" 를 먼저 묻는다 — 미디어 관리 권한이 있으면 시스템 창 없이 바로 옮겨지기 때문이다.
- 설정에서 자동 백업·업로드 목록·Drive 보기·중복·카테고리·자동 태그 줄을 뺀다(각 칸으로 갔다). 갤러리 상단바의 톱니도 뺀다.

## 백업 배지

| 상태 | 표시 | 기본 |
|---|---|---|
| 올라감 | 구름 ✓ | **켬**(설정 → 갤러리 → "백업된 사진에 표시" 로 끌 수 있다) |
| 대기·올리는 중 | 구름 ↑ | 항상 |
| 실패 | 구름 ✕ | 항상 |

대기·실패는 업로드 큐(`upload_tasks`)의 미디어 ID로, 올라감은 원장으로 정한다(올라간 것이 실패보다 앞선다 — 예전 배치의 실패 줄이
남아 있어도 원장에 있으면 올라간 것이다).
