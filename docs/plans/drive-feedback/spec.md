# Drive 사진의 되먹임 — 받기·휴지통이 무엇을 했는지 보이게, "Drive 에서 열기" 는 앱 안에서

2026-10-08. 기기 확인 뒤 사용자 지적:
1. 상세보기 "Drive 에서 열기" 가 Drive 앱의 계정 선택을 띄운다 → **A(앱 안에서 보기)로** 결정
2. "기기로 받았는데 받아졌는지도 모르게 받아졌다. 모달·메시지·상태바로 알려 주면 좋겠다. 연구해."
3. "어느 휴지통인지 모르겠다. 실행 취소인지 뭔지도 못 알아보겠다."

## 1. 원인 — 기기·코드로 확인

| 증상 | 원인 |
|---|---|
| 넘겨 보기에서 받기·휴지통을 눌러도 아무 말이 없다 | 스낵바("받기 시작", "휴지통으로 옮김 [실행 취소]")는 **Drive 사진 화면의 Scaffold** 에 뜬다. 넘겨 보기는 그 위를 덮는 전체 화면 `Dialog` 라 **창 뒤에 가려진다**. 2·3 의 공통 원인 |
| 다 받았다는 알림을 못 봤다 | 완료 알림이 업로드 채널(`IMPORTANCE_LOW`)에 조용히 올라간다 — 소리·팝업 없음, 삼성은 조용한 알림의 상태바 아이콘을 숨긴다. 눌러도 받은 사진이 열리지 않는다(기기 `dumpsys notification`: id 3312, importance=2) |
| 받은 뒤에도 화면이 그대로다 | 받은 파일을 원장에 잇지 않아 칸의 ☁ 와 "이 기기에는 없음" 이 그대로 남는다 |
| "휴지통" 이 어디인지 모르겠다 | 앱에는 **폰 휴지통**(앨범 칸, MediaStore)과 **Drive 휴지통**이 둘 다 있는데 문장이 "휴지통으로 옮겼습니다" 뿐이다 |

## 2. 무엇으로 알릴까 — 견준 것

| 수단 | 맞는 때 | 판단 |
|---|---|---|
| 스낵바 | 방금 한 일의 짧은 결과 + 되돌리기 하나(Material 지침) | **쓴다** — 단, 지금 보이는 창(넘겨 보기) 안에 띄워야 한다 |
| 알림 | 사용자가 앱을 떠났을 수도 있는 **백그라운드 작업의 끝** | **쓴다** — 완료 알림을 따로 채널로, 상태바에 아이콘이 남게, 누르면 받은 사진이 열리게. 소리는 없다(사진 몇 장에 소리는 과하다) |
| 모달(대화상자) | 사용자의 결정이 필요할 때 | **안 쓴다** — 받기는 결정할 것이 없다. 매번 닫아야 하는 창은 여러 장 받을 때 방해다 |
| 화면 상태 변화 | 결과가 화면에 남아야 할 때 | **쓴다** — 받은 사진의 ☁ 가 사라지고 "이 기기에도 있음" 으로 바뀌면, 스낵바를 놓쳐도 결과가 남는다 |

## 3. 바꾸는 것

1. **넘겨 보기 안에 스낵바 자리**(`DriveMediaPager` 에 `SnackbarHost`). 받기·휴지통·실행 취소·오류가 사진 위에 보인다. 폴더 화면도 같다.
2. **받기**
   - 누르면: "기기로 받는 중… 끝나면 알려 드릴게요"
   - 끝나면(앱 안에 있으면) 스낵바 "갤러리에 저장했습니다 [보기]" → 기기 사진 상세보기로. 여러 장이면 "N장을 갤러리에 저장했습니다"
   - 끝나면(항상) 완료 알림 — 새 채널 "다운로드 완료"(기본 중요도, 소리 없음). 누르면 그 사진이 열린다
   - 받은 사진을 **원장에 잇는다**(Drive 파일 ID ↔ 새 기기 사진). ☁ 가 사라지고 "이 기기에도 있음", 갤러리에서도 백업됨 ✓
3. **휴지통 문장에 "Drive" 를 넣는다** — "Drive 휴지통으로 옮겼습니다 [실행 취소]". 폰 휴지통과 헷갈리지 않게
4. **상세보기 "Drive 에서 열기" → 앱 안 넘겨 보기**(결정 A). 원장의 파일 ID 로 메타데이터를 읽어 같은 넘겨 보기로 띄운다.
   다른 계정으로 올린 파일처럼 지금 계정이 읽을 수 없으면 까닭을 말하고 "Drive 앱에서 열기" 를 대신 준다.
