# 다른 계정 업로드 — 주 계정은 그대로, 잠깐 B 로 올리고 A 에게 공유

2026-09-27 시작. 검토는 `docs/MULTI_GOOGLE_ACCOUNT.md` §6.

## 1. 요구

> A 는 연결된 채로 둔다. "다른 계정 업로드" 를 누르면 잠깐 B 로 올리고, A 에게 공유까지 하고,
> B 는 풀린다. 연결 해제는 하지 않는다. **업로드하는 동안은 B 가 기기에 있어도 되지만 계속 남으면 안 된다.**

## 2. 앱이 못 하는 것 하나 — 먼저 적는다

**앱은 기기의 Google 계정을 지울 수 없다.** 안드로이드는 계정을 만든 쪽(Google 인증자)만 지울 수 있게 한다.
그래서 "안 남기기" 는 앱이 **업로드가 끝나는 순간 계정 설정으로 바로 보내 주는 것**까지다.
B 가 원래 기기에 있던 계정이면(S23+ 처럼) 그냥 두면 된다.

## 3. 흐름

```
선택 → ⋮ → "다른 Google 계정으로 업로드"
  ① 계정 선택 창(항상 뜬다) → B
  ② B 의 Drive 에 "Easy Gallery" 를 찾거나 만든다
  ③ 그 폴더를 A 에게 공유(읽기, 알림 메일 없음) — 폴더 한 번이면 안의 파일은 권한을 물려받는다
  ④ A 가 읽기 권한을 옵트인했으면 A 의 "볼 수 있는 폴더" 에 그 폴더를 더한다
  ⑤ 고른 사진을 큐에 넣는다 — 대상 계정은 google:<B 이메일>, 폴더는 ②
  ⑥ 워커가 B 의 토큰으로 올린다
  ⑦ B 의 것이 다 끝나면 알림 + 갤러리 배너: "기기에서 B 를 지우려면 [계정 설정]"
```

A 의 연결 정보(`accountEmail`·업로드 폴더·보기 폴더·읽기 권한)는 **한 번도 건드리지 않는다.**

## 4. 설계

### 4.1 B 의 토큰 — Play 서비스, 계정만 바꿔서

- 시작: `authorize` 를 계정 지정 없이 + `Prompt.SELECT_ACCOUNT`. 지정하지 않으면 Play 서비스가 전에 쓴
  계정(A)을 조용히 골라버릴 수 있어서 **선택 창을 강제**한다. scope 는 `drive.file` 하나.
- 누구를 골랐는지는 결과에 없다. 받은 토큰으로 Drive `about` 을 불러 이메일을 얻는다.
- **A 를 고르면 되돌린다** — "이미 연결된 계정입니다". 그걸 허용하면 그냥 일반 업로드다.
- 워커: `GuestTokenProvider(B)` 가 `setAccount(B)` 로 매번 받는다. B 가 기기에 있는 동안은 동의 없이 조용히
  나온다. **앱이 죽어도 이어 올릴 수 있다** — 토큰을 우리가 들고 있지 않고 필요할 때 다시 받으니까.
- 끝날 때 revoke 는 부르지 않는다(검토 §6.3 — 그 사용자의 이 프로젝트 권한 전부를 지운다).

### 4.2 B 전용 저장소

`accountId = "google:<B 이메일>"`. `StorageRegistry` 가 이 접두어를 보고 `GuestDriveStorageFactory` 로 만든다.
B 전용 OkHttpClient(인터셉터에 `GuestTokenProvider(B)`) → Retrofit `DriveApi` → `DriveRestRepository` +
`DriveUploader`. 기존 Drive 코드를 그대로 쓰고 **토큰 공급자만 갈아 끼운다.**

### 4.3 원장

`destinationFor("google:<B>")` → `drive:<B>`. B 가 나중에 주 계정이 되어도 기록이 그대로 이어진다.
A 의 백업 표시에는 섞이지 않고, 다음에 또 B 로 올리면 이미 있는 것은 건너뛴다.

### 4.4 폴더 공유 — `permissions.create`

```
POST files/{folderId}/permissions?sendNotificationEmail=false
{ "type": "user", "role": "reader", "emailAddress": "<A>" }
```

`drive.file` 로 허용된다(앱이 만든 폴더). 이미 공유돼 있으면 같은 권한이 한 번 더 생기지 않는다.

### 4.5 끝났다는 것 — 알림과 배너

워커가 한 번 돌 때 처리한 B 계정들을 모아, 끝에 그 계정의 **남은 항목이 0** 이면 알린다.
알림만으로는 부족하다 — 알림을 꺼 둔 사용자는 "지우라" 는 말을 못 듣는다. 그래서 `guestCleanupEmail` 을
설정에 남겨 두고 갤러리 배너로도 보인다. 사용자가 닫으면 지운다. [계정 설정] 은
`Settings.ACTION_SYNC_SETTINGS`(기기의 계정 목록)를 연다.

## 5. 범위 밖

- B 를 앱에 계정으로 **기억**하기. 요구가 "안 남기" 라서 매번 선택 창에서 고른다.
- A 가 읽기 권한을 옵트인하지 않았을 때 그 자리에서 동의 받기. 배너가 "공유 문서함에서 볼 수 있다" 고 안내한다.
- 여러 B 를 동시에. 막지는 않지만 따로 다듬지 않는다.

## 6. 누구의 폴더인지 보여준다 (2026-09-27 추가)

기기 확인에서 나온 불만: **A 의 폴더도 "Easy Gallery", B 의 폴더도 "Easy Gallery"** 라 어느 쪽인지 알 수 없다.
처음에는 보기 폴더 이름에 `· <B 이메일>` 을 덧붙였는데 모자랐다.

- 목록 한 줄은 `maxLines = 1` 이라 긴 이름은 뒤가 잘린다 — 정작 이메일이 잘린다.
- 폴더 안에 들어가면 제목이 이름뿐이라 A 의 것과 같아 보인다.
- 피커의 공유 문서함에는 B 가 붙인 이름("Easy Gallery")이 그대로 나온다.

**이름에 섞지 않고 소유자를 따로 보인다.** Drive 가 주는 `owners` 를 받아 둔다.

| 자리 | 보이는 것 |
|---|---|
| Drive 루트 한 줄 | 부제에 `내 계정` 또는 `nhnpopt0@gmail.com`(+ `보기 전용`) |
| 피커의 공유 문서함 | 폴더마다 부제에 소유자 |
| 남의 폴더 안 | 상단 부제가 "Google Drive" 대신 `nhnpopt0@gmail.com 의 폴더` |

- `DriveEntry.ownerEmail` — 소유자 이메일(나일 수도 있다). null 은 모른다는 뜻. "내 계정" 은 화면이 연결 이메일과 비교해 정한다.
- `ViewFolder.ownerEmail` 로 저장한다. 고를 때 목록에서 받은 값을 넣고, 이미 저장된 것(소유자 없음)은 루트를 읽을 때
  한 번 물어서 채운다(읽기 권한이 있을 때만 — `files.get` 이 된다).
- 다른 계정 업로드가 더하는 보기 폴더 이름은 **폴더 이름 그대로**("Easy Gallery")에 소유자만 따로 둔다. 이미 `· 이메일` 을
  붙여 저장된 것은 소유자를 채울 때 그 꼬리를 뗀다.
- 이동 경로를 따라 들어가도 소유자를 잃지 않게 `DriveBrowserKey.ownerEmail` 로 넘긴다(`readOnly` 와 같은 방식).
- 지정 폴더(업로드 대상)는 `drive.file` 에서 폴더를 읽을 수 없어(404) 소유자를 모른다. 부제를 비워 둔다.
